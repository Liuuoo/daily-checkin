### 题目：最长上升子序列 (Longest Increasing Subsequence, LIS)

这是一道经典的动态规划问题，常用于衡量对序列处理能力的理解。

#### 1. 题目描述
给定一个无序的整数数组 `nums`，找到其中最长严格递增子序列的长度。
**子序列**是由数组派生而来的序列，删除（或不删除）数组中的元素而不改变其余元素的顺序。例如，`[3, 6, 2, 7]` 是 `[0, 3, 1, 6, 2, 2, 7]` 的子序列。

**示例：**
- 输入：`nums = [10, 9, 2, 5, 3, 7, 101, 18]`
- 输出：`4`
- 解释：最长的上升子序列是 `[2, 3, 7, 101]`。

---

#### 2. 思路分析
这道题有两种主流解法：

**方法一：动态规划 (DP)**
*   **定义状态**：`dp[i]` 表示以 `nums[i]` 结尾的最长上升子序列的长度。
*   **状态转移方程**：对于每一个 `i`，遍历 `0` 到 `i-1` 的所有位置 `j`。如果 `nums[i] > nums[j]`，则可以将 `nums[i]` 接在 `nums[j]` 后面，更新 `dp[i] = max(dp[i], dp[j] + 1)`。
*   **复杂度**：时间复杂度为 $O(n^2)$，空间复杂度为 $O(n)$。

**方法二：贪心 + 二分查找 (优化方案)**
*   **核心思想**：为了让上升子序列尽可能长，我们希望序列增长得尽可能“慢”。因此，我们维护一个数组 `tails`，其中 `tails[i]` 存储长度为 `i+1` 的最长上升子序列的末尾最小元素。
*   **操作**：遍历 `nums`，若当前元素大于 `tails` 的末尾元素，直接追加；否则，使用二分查找在 `tails` 中找到第一个大于等于当前元素的位置并替换它。
*   **复杂度**：时间复杂度为 $O(n \log n)$，空间复杂度为 $O(n)$。

---

#### 3. Python 代码实现 (采用 $O(n \log n)$ 优化方案)

```python
import bisect

def length_of_lis(nums):
    if not nums:
        return 0
    
    # tails 数组存储的是：长度为 i+1 的递增子序列的最小末尾元素
    tails = []
    
    for x in nums:
        # 使用二分查找找到第一个大于等于 x 的位置
        # bisect_left 返回的是插入点索引
        idx = bisect.bisect_left(tails, x)
        
        # 如果 idx 等于当前 tails 的长度，说明 x 比所有已知的末尾元素都大，
        # 此时最长上升子序列长度增加
        if idx == len(tails):
            tails.append(x)
        else:
            # 否则，替换掉那个大于等于 x 的元素，使得该长度序列的末尾变得更小
            # 这为后续加入更大的元素留出了更多空间（贪心策略）
            tails[idx] = x
            
    return len(tails)

# 测试代码
if __name__ == "__main__":
    test_case = [10, 9, 2, 5, 3, 7, 101, 18]
    print(f"输入数组: {test_case}")
    print(f"最长上升子序列长度: {length_of_lis(test_case)}")
```

---

#### 4. 复杂度分析

*   **时间复杂度：$O(n \log n)$**
    *   我们遍历了一次数组 `nums`，共 $n$ 次操作。
    *   在循环中，使用了 `bisect_left` 进行二分查找，其时间复杂度为 $O(\log n)$。
    *   总时间复杂度为 $O(n \log n)$，在处理大规模数据（如 $10^5$ 级别）时表现优异。

*   **空间复杂度：$O(n)$**
    *   我们需要一个额外的数组 `tails` 来存储中间状态，在最坏情况下（数组本身就是升序的），`tails` 的长度将达到 $n$。
