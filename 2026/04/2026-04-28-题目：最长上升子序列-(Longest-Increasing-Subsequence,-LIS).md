### 题目：最长上升子序列 (Longest Increasing Subsequence, LIS)

这是一道经典的动态规划（DP）入门题，同时也是面试中考察算法思维的常青树。

#### 1. 题目描述
给定一个无序的整数数组 `nums`，找到其中最长严格递增子序列的长度。

**示例：**
*   输入：`nums = [10, 9, 2, 5, 3, 7, 101, 18]`
*   输出：`4`
*   解释：最长的上升子序列是 `[2, 3, 7, 101]` 或 `[2, 5, 7, 101]` 或 `[2, 5, 7, 18]`。

---

#### 2. 思路分析

**解法一：动态规划（DP）**
*   **状态定义**：设 `dp[i]` 表示以 `nums[i]` 结尾的最长上升子序列的长度。
*   **状态转移方程**：对于每个 `i`，遍历 `0` 到 `i-1` 的所有位置 `j`。如果 `nums[i] > nums[j]`，则可以将 `nums[i]` 接在 `nums[j]` 后面，此时 `dp[i] = max(dp[i], dp[j] + 1)`。
*   **初始状态**：每个元素自身至少是一个长度为 1 的子序列，所以 `dp` 数组初始化全为 1。

**解法二：贪心 + 二分查找（优化版）**
为了进一步优化，我们可以维护一个数组 `tails`，其中 `tails[i]` 存储所有长度为 `i+1` 的递增子序列的尾部最小值。
*   遍历 `nums` 中的每个数字 `x`：
    *   如果 `x` 大于 `tails` 的最后一个元素，直接追加到 `tails` 末尾。
    *   否则，在 `tails` 中使用二分查找找到第一个大于等于 `x` 的元素，并将其替换为 `x`。
*   最终 `tails` 的长度即为 LIS 的长度。

---

#### 3. Python 代码实现

下面展示的是**时间复杂度为 O(n log n)** 的优化算法：

```python
import bisect

def length_of_lis(nums):
    if not nums:
        return 0
    
    # tails 数组用于存储递增子序列的尾部元素
    tails = []
    
    for x in nums:
        # 使用 bisect_left 在 tails 中查找第一个大于等于 x 的位置
        # 这相当于二分查找，保证了 tails 始终是有序的
        idx = bisect.bisect_left(tails, x)
        
        # 如果 idx 等于 tails 长度，说明 x 比所有已知的尾部元素都大
        if idx == len(tails):
            tails.append(x)
        else:
            # 否则，用 x 替换掉那个较大的值，以尝试构建更长的序列
            # 这是一种“贪心”策略：让结尾元素尽可能小，后续更易增长
            tails[idx] = x
            
    return len(tails)

# 测试代码
nums = [10, 9, 2, 5, 3, 7, 101, 18]
print(f"最长上升子序列长度为: {length_of_lis(nums)}")
```

---

#### 4. 复杂度分析

*   **时间复杂度：O(n log n)**
    *   我们需要遍历一遍数组，共 $n$ 次。
    *   在循环内部，使用 `bisect_left` 进行二分查找，复杂度为 $O(\log n)$。
    *   总时间复杂度为 $O(n \log n)$，远优于朴素 DP 的 $O(n^2)$。

*   **空间复杂度：O(n)**
    *   我们需要维护一个额外的 `tails` 数组，最坏情况下其长度与输入数组 `nums` 相等，因此空间复杂度为 $O(n)$。

---

**博主结语：**
LIS 的贪心优化思想非常巧妙。通过维护“尾部最小值”，我们实际上是在不断尝试用更小的数来“接替”现有序列的尾部，从而为后续扩展留出更大的空间。这种在 DP 基础上引入二分查找的技巧，是处理序列类题目时提升性能的关键手段。
