# Docker 生产环境最佳实践：从“能跑”到“稳健”

在容器化应用普及的今天，很多团队仅停留在“把应用打包成 Docker 镜像”的阶段。但在生产环境中，一个配置不当的 Dockerfile 或容器运行参数，往往会导致镜像臃肿、构建缓慢、内存泄漏甚至是严重的安全隐患。

本文将从**镜像构建优化**、**运行时安全**与**资源限制**三个维度，分享实战中的最佳实践。

---

### 1. 镜像构建：追求“小而精”

臃肿的镜像不仅增加存储成本，还会延长 CI/CD 流水线的拉取时间，并扩大攻击面。

#### 核心策略：多阶段构建 (Multi-stage Builds)
不要在生产镜像中保留源代码、构建工具（如 Maven/Go/Node.js）或缓存文件。

```dockerfile
# 第一阶段：构建环境
FROM golang:1.21-alpine AS builder
WORKDIR /app
COPY . .
# 禁用 CGO 以获得静态链接的二进制文件
RUN CGO_ENABLED=0 GOOS=linux go build -o myapp main.go

# 第二阶段：生产环境（仅包含运行所需文件）
FROM alpine:3.18
RUN apk add --no-cache ca-certificates
WORKDIR /root/
# 只从 builder 阶段拷贝二进制文件
COPY --from=builder /app/myapp .

# 使用非 root 用户运行，提升安全性
RUN adduser -D appuser
USER appuser

EXPOSE 8080
CMD ["./myapp"]
```

**关键点：**
*   **使用轻量级基础镜像**：首选 `alpine` 或 `distroless`。
*   **合并 RUN 指令**：减少层数（Layer），每个 `RUN` 都会生成一个新的层。

---

### 2. 运行时配置：资源与隔离

容器默认是不受限制的，如果应用出现内存泄漏，可能会导致宿主机物理内存耗尽，触发 OOM Killer 导致整个节点崩溃。

#### 限制资源 (Resource Limits)
在 `docker run` 或 Kubernetes 的 `resources` 字段中，务必设置 `limits` 和 `requests`。

```yaml
# Kubernetes 示例
resources:
  requests:
    memory: "256Mi"
    cpu: "250m"
  limits:
    memory: "512Mi"
    cpu: "500m"
```

**实战建议：**
*   **Requests** 是调度依据，**Limits** 是硬性上限。
*   一定要设置 `limits`，防止单个容器吃光宿主机资源。
*   在 Java 应用中，记得开启 `-XX:+UseContainerSupport`（JDK 8u191+），否则 JVM 无法感知容器的内存限制，导致频繁 OOM。

### 3. 日志与健康检查：生产的“眼睛”

很多开发者习惯将日志写入容器内部的文件，这在容器重启后会丢失。

#### 日志最佳实践
*   **遵循 12 要素**：将日志直接输出到 `stdout` 和 `stderr`。
*   Docker 默认使用 `json-file` 驱动，可以通过 `daemon.json` 配置日志滚动，防止磁盘写满：

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

#### 健康检查 (Healthcheck)
不要依赖 Docker 容器进程是否存活，而要依赖应用是否“可用”。

```dockerfile
# 在 Dockerfile 中定义
HEALTHCHECK --interval=30s --timeout=3s \
  CMD curl -f http://localhost:8080/health || exit 1
```

---

### 4. 生产环境避坑清单 (Checklist)

1.  **拒绝使用 `latest` 标签**：在生产环境中始终使用具体的版本号（如 `v1.2.3`）或 Git Commit Hash，否则版本回滚将变得不可控。
2.  **避免 `root` 权限**：始终在 Dockerfile 中创建专用用户并使用 `USER` 指令。
3.  **使用 `.dockerignore`**：这是常被忽略的一点。务必将 `.git`、`node_modules`、`logs` 等非必要文件排除在外，否则 `COPY . .` 会极大拖慢构建速度，甚至泄露敏感代码。
4.  **配置只读文件系统**：如果应用不需要写磁盘，运行容器时添加 `--read-only` 参数，极大提升安全性。

### 结语

Docker 的强大之处在于其标准化能力，但“标准化”并不等同于“默认配置”。生产环境的运维实践，本质上是在**便捷性**、**性能**与**安全性**之间寻找平衡点。通过多阶段构建减小体积，通过资源限制保障稳定性，通过非 root 用户构筑安全防线，是每位工程师迈向高阶运维的必经之路。
